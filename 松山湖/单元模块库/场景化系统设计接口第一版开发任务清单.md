# 场景化系统设计接口第一版开发任务清单

## 1. 开发目标

第一版目标不是重写优化模型，而是在现有德国/松山湖 CCHP 优化代码外层增加标准接口：

```text
scenario.yaml / Excel
  -> 默认配置补齐
  -> 典型日准备
  -> 转成当前 case_config
  -> 调用现有 CCHP 优化
  -> 输出标准设计结果包
```

第一版必须跑通：

1. 松山湖 YAML 场景。
2. 德国 YAML 场景。
3. Excel 场景整理模板的读取和校验。
4. 典型日读取/生成接口。
5. 标准结果输出。

## 2. 建议新增目录结构

```text
ies_design/
├── __init__.py
├── cli.py                         # design.py 的主流程实现
├── scenario_loader.py             # 读取 scenario.yaml
├── excel_parser.py                # 读取课题组场景整理模板.xlsx
├── defaults_resolver.py           # 合并默认库、模板、用户覆盖
├── schema_validator.py            # 校验场景、设备、数据、价格、典型日
├── typical_day.py                 # 典型日读取、月模板生成、8760聚类
├── current_cchp_adapter.py        # resolved_scenario -> 当前 case_config
├── design_optimizer.py            # 调用现有 run_comparative_study
├── result_exporter.py             # 输出标准设计结果包
├── reports.py                     # validation/design/typical_day 报告文本生成
└── defaults/
    ├── device_library.yaml
    ├── system_templates.yaml
    ├── scenario_catalog.yaml
    ├── component_mapping.yaml
    └── optimization_defaults.yaml

design.py                          # 顶层命令行入口，调用 ies_design.cli

scenarios/
├── german/
│   ├── scenario.yaml
│   └── README.md
└── songshan_lake/
    ├── scenario.yaml
    └── README.md
```

说明：

- `ies_design/` 是新接口层，不直接破坏现有 `run.py`、`operation.py`、`cchp_gaproblem.py`。
- `design.py` 是用户入口，区别于论文实验入口 `run.py`。
- `defaults/` 放默认设备库、系统模板、场景类型目录。
- `scenarios/` 放真实可运行场景配置。

## 5. 推荐优先级

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 | 默认配置 + 当前 CCHP 适配器 | 决定能否跑通现有德国/松山湖。 |
| P0 | `design.py --scenario` | 中期接口主入口。 |
| P0 | 结果输出标准化 | 中期要交付“配置结果”。 |
| P1 | 典型日模块 | 支持 8760 自动生成和月典型日。 |
| P1 | Excel 解析 | 支持师弟整理的场景表。 |
| P2 | 15 场景完整 catalog | 展示扩展性。 |
| P2 | component_mapping / 通用 ModelBuilder | 后续扩展氢、蒸汽等场景。 |

## 6. 开发风险与注意事项

1. **不要先重构现有优化内核。** 第一版通过适配器调用现有代码，降低风险。
2. **不要把氢、蒸汽等预留场景误写成已支持计算。** 必须用 `implementation.status` 区分。
3. **结果输出要面向用户。** 不只保存 Pareto CSV，还要有 `design_report.md` 和 `design_summary.csv`。
4. **配置解析要可追溯。** 输出 `resolved_scenario.yaml`，方便复现。
5. **Excel 解析要容忍缺失。** 师弟整理资料时很多数据会缺，缺失应生成缺口报告，而不是直接崩溃。
6. **项目索引要同步更新。** 新增 `design.py`、`ies_design/`、`scenarios/` 后，需要更新 `项目索引目录.md`。
