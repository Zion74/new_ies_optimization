# 场景化系统设计接口使用说明书

本文档面向合作者、导师和后续整理场景数据的同学，说明第一版场景化系统设计接口如何使用、需要提供哪些数据、如何调整参数，以及如何解读输出结果。

## 1. 系统能做什么

第一版系统用于在给定场景、系统结构和负荷/资源数据后，调用单元模块库与现有优化模型，输出设备容量配置结果。

当前已经跑通的真实计算后端是电-热-冷-气 CCHP 结构：

```text
场景 YAML / Excel 模板
  -> 默认设备库和系统模板补齐
  -> 输入校验
  -> 转换为当前 case_config
  -> 调用现有 CCHP 双层优化代码
  -> 导出标准设计结果包
```

当前可真实优化的场景：

- 德国案例：`ies_design/scenarios/german/scenario.yaml`
- 松山湖案例：`ies_design/scenarios/songshan_lake/scenario.yaml`

当前已预留但不声明可真实优化的内容：

- 氢、蒸汽、甲醇、氧等负荷需求。
- 电解槽、储氢、蒸汽锅炉、余热回收、生物质锅炉、潮汐发电等设备。
- 15 种应用场景目录。

这些内容可以进入 Excel/YAML 配置和校验层，但当前 `current_cchp` 后端不会把它们映射成真实 Pyomo/oemof 组件。

## 2. 用户最小需要提供哪些输入

如果只想跑通系统设计，用户最小需要提供以下 6 类信息。

| 输入类别 | 是否必需 | 说明 |
|---|---|---|
| 场景信息 | 必需 | 场景编号、场景名称、场景类型、地点、币种。 |
| 用户负荷需求 | 必需 | 例如电/热/冷/氢/蒸汽需求。当前真实优化后端支持电、热、冷。 |
| 能源输入与资源 | 必需 | 例如电网购电、天然气、太阳辐射、风速、环境温度、余热。 |
| 候选设备 | 必需 | 哪些设备可选、是否优化容量、容量上限。 |
| 价格参数 | 必需 | 电价、气价、容量费。没有容量费时填 0。 |
| 典型日/时间序列设置 | 必需 | 可提供已有典型日，也可由 8760 数据聚类生成。 |

设备技术经济参数可以不全部由用户提供。程序会先使用内置默认设备库补齐；用户只需要覆盖自己确定的参数，例如设备容量上限、COP、效率、投资成本。

## 3. 两种输入方式

### 3.1 YAML 输入

适合开发者、已经整理好的真实场景，推荐用于正式运行。

示例：

```bash
python design.py --scenario "松山湖/单元模块库/ies_design/scenarios/songshan_lake/scenario.yaml" --validate-only
uv run python design.py --scenario "松山湖/单元模块库/ies_design/scenarios/songshan_lake/scenario.yaml" --mode test
```

YAML 中最关键的部分：

```yaml
scenario:
  id: songshan_lake
  name: 松山湖科研产业园
  scenario_type: industrial_park_pv_geothermal_waste_heat
  currency: CNY

system:
  template: cchp_ehc_base

energy_carriers:
  demands: [electricity, heat, cooling]
  inputs: [natural_gas]
  resources: [solar_resource, temperature]

data:
  input_type: timeseries_8760
  load_file: data/songshan_lake_data.csv
  typical_day_file: data/songshan_lake_typical.xlsx

devices:
  pv:
    library_id: pv_standard
    enabled: true
    optimize_capacity: true
    capacity_ub_kw: 1000
```

### 3.2 Excel 输入

适合给课题组同学整理场景资料、验收展示和非开发人员填写。

模板路径：

```text
松山湖/单元模块库/课题组场景整理模板.xlsx
```

导出 Excel 中间场景包：

```bash
uv run python design.py --excel "松山湖/单元模块库/课题组场景整理模板.xlsx" --export-scenario --output tmp_excel_export
```

导出后会生成：

- `scenario.yaml`
- `typical_profiles.csv`
- `input_resource_profiles.csv`
- `data_gaps.csv`
- `excel_parse_warnings.txt`

空白模板也可以解析，但会提示缺少场景编号、场景名称、负荷曲线等信息。填写完整后，再把导出的 `scenario.yaml` 用作正式输入。

## 4. Excel 每个 sheet 怎么填

| Sheet | 作用 | 关键字段 |
|---|---|---|
| `01_场景信息` | 描述场景基本信息 | `scenario_id`, `scenario_name`, `scenario_type`, `location`, `currency` |
| `02_场景能源配置` | 选择用户需求、能源输入和资源 | `item_id`, `item_group`, `enabled`, `required` |
| `03_月度用户需求` | 填月总量，可用于校验典型日 | `month`, `demand_id`, `energy_amount`, `unit`, `days` |
| `04_用户负荷需求曲线` | 填每月典型日逐时负荷 | `profile_id`, `month`, `hour`, `demand_id`, `value`, `unit` |
| `05_能源输入与资源曲线` | 填购能、可再生资源、余热和环境参数 | `input_id`, `input_type`, `carrier_id`, `value`, `unit` |
| `06_候选设备配置` | 填候选设备与容量边界 | `device_id`, `library_id`, `enabled`, `capacity_ub`, `power_ub` |
| `07_价格与排放参数` | 填电价、气价、容量费、排放因子 | `param_id`, `carrier_id`, `param_type`, `value` |
| `08_资料来源与缺口` | 记录数据来源和缺口 | `data_item`, `status`, `source_file`, `missing_or_issue` |

填写建议：

1. 先填 `01`、`02`、`06`、`07`、`08`。
2. 如果有 8760 数据，优先保留原始 8760 文件，并在 YAML 中指定 `load_file`。
3. 如果暂时只有典型日，可以每个月填 1 个 24h 曲线，后续用 `monthly_template` 生成 12 个典型日权重。
4. 没有数据不要随便填 0，应在 `08_资料来源与缺口` 说明缺口。

## 5. 典型日怎么处理

系统支持三类典型日来源。

### 5.1 已有典型日

已有文件需要包含三列：

```text
typicalDayId, weight, days
```

含义：

- `typicalDayId`: 典型日在全年 365 天中的编号，1-based。
- `weight`: 该典型日代表的天数。
- `days`: 被代表的天编号，用英文逗号连接。

### 5.2 每月 1 个典型日

适合只有每个月一个 24h 曲线的早期场景。

命令：

```bash
python design.py --generate-typical-days monthly_template --output tmp_typical_days
```

输出：

- `typical_days.csv`
- `typical_day_report.md`

### 5.3 从 8760 数据聚类

适合用户已经有全年逐时数据。

命令示例：

```bash
python design.py --generate-typical-days cluster_from_8760 --data-file data/songshan_lake_data.csv --columns "ele_load(kW)" "heat_load(kW)" "cool_load(kW)" --output tmp_cluster_days
```

第一版实现了确定性的 `kmeans_medoid` 近似流程：先按天构造向量，再聚类，最后选每个簇中最接近中心的真实日作为典型日。

## 6. 如何调整参数

### 6.1 调整优化规模

测试模式：

```bash
uv run python design.py --scenario "松山湖/单元模块库/ies_design/scenarios/songshan_lake/scenario.yaml" --mode test
```

自定义规模：

```bash
python design.py --scenario "松山湖/单元模块库/ies_design/scenarios/songshan_lake/scenario.yaml" --mode custom --nind 20 --maxgen 20 --methods std euclidean --workers 4 --dry-run
```

参数含义：

- `--nind`: 种群规模。
- `--maxgen`: 最大迭代代数。
- `--methods`: 优化目标/对比方法，例如 `economic_only std euclidean pearson ssr`。
- `--workers`: 并行进程数。
- `--dry-run`: 只检查会传给优化器的参数，不实际求解。

### 6.2 调整设备容量边界

在 YAML 的 `devices` 中修改：

```yaml
devices:
  electric_chiller:
    library_id: electric_chiller
    enabled: true
    optimize_capacity: true
    capacity_ub_kw: 5000
```

### 6.3 调整设备技术经济参数

通过 `overrides` 覆盖默认设备库：

```yaml
devices:
  chp:
    library_id: chp_gas_turbine
    enabled: true
    capacity_ub_kw: 800
    overrides:
      eta_e: 0.423
      eta_h: 0.42
      invest_coeff: 380.0
```

### 6.4 调整电价和气价

```yaml
prices:
  electricity:
    type: flat
    unit: CNY_per_kWh
    value: 0.6746
  gas:
    type: flat
    unit: CNY_per_kWh
    value: 0.45
  capacity_charge:
    unit: CNY_per_kW_year
    value: 0
```

## 7. 输出结果怎么看

真实优化运行后，结果目录位于：

```text
Results/design__{scenario_id}__{mode}__{timestamp}/
```

标准结果包包含：

| 文件 | 用途 |
|---|---|
| `design_report.md` | 推荐优先查看。包含场景、输入数据、系统结构、优化设置和推荐配置。 |
| `design_summary.xlsx` | Excel 展示版推荐方案，适合给合作者/导师查看。 |
| `design_summary.csv` | 长表结果，适合后续程序处理和多能源扩展。 |
| `design_summary_wide.csv` | 宽表结果，适合快速人工查看。 |
| `pareto_solutions.csv` | 汇总所有 Pareto 解，并标记是否超过成本阈值。 |
| `resolved_scenario.json` | 本次实际运行使用的完整场景配置。 |
| `validation_report.md` | 输入校验报告。 |
| `comparison_report.md` | 现有优化代码生成的原始对比报告。 |

推荐先看：

1. `validation_report.md`
2. `design_report.md`
3. `design_summary.xlsx`
4. `pareto_solutions.csv`

## 9. 当前限制

1. 第一版真实优化后端只支持当前 CCHP 结构，即电、热、冷、天然气、光伏、风电、储能等。
2. 氢、蒸汽、甲醇等设备和负荷已在接口层预留，但还没有真实 Pyomo/oemof 组件映射。
3. Excel 模板导出的 `scenario.yaml` 主要用于整理和转换，空白模板不能直接优化。
4. 真实优化建议使用 `uv run python ...`，因为系统 Python 可能没有 `geatpy`、`openpyxl` 等依赖。
5. 现有原始 `comparison_report.md` 中个别历史货币符号可能沿用旧逻辑；第一版标准结果以 `design_report.md` 和 `design_summary.xlsx` 为准。

## 10. 给合作者的数据整理要求

请每个场景至少整理：

- 场景名称、地点、行业类型、场景类型。
- 需要满足的用户负荷：电、热、冷、蒸汽、氢、天然气等。
- 可用能源输入和资源：电网、天然气、太阳辐射、风、余热、地热、环境温度等。
- 逐时负荷数据：优先 8760；没有则提供每月典型日 24h 曲线。
- 候选设备：设备类型、是否可选、容量上限、已知效率或 COP、已知投资成本。
- 能源价格：电价、气价、容量费，若有分时价格需按 24h 给出。
- 数据来源与缺口：每个关键数据来自哪个文件/表格/页码，缺失项说明原因。

如果某个数据不确定，不要随意补数；先在 `08_资料来源与缺口` 中说明，后续由建模人员决定是否采用默认值、估算值或暂不优化。
