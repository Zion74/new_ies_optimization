# 多能转换单元模块库使用说明书

## 1. 这套模块库解决什么问题

这套模块库面向“用户已经给定场景和系统结构”的综合能源系统设计任务。用户提供系统结构、负荷数据、能源输入/资源曲线和候选设备信息后，程序完成：

1. 读取并校验场景输入；
2. 调用默认设备库补齐技术经济参数；
3. 将用户设备映射为模块库中的标准仿真组件；
4. 按拓扑装配成可计算的系统对象；
5. 调用当前可用后端进行容量配置或调度求解；
6. 输出标准化容量配置结果和验收报告。

当前不是动态生成任意拓扑，而是在用户给定场景结构或选择系统模板的前提下完成模块调用和配置计算。

## 2. 当前支持的两条后端路线

| 后端 | 适用场景 | 作用 | 当前状态 |
|---|---|---|---|
| `current_cchp` | 冷热电 CCHP 固定结构，例如松山湖、德国 | 适配旧论文实验代码，完成真实容量优化和典型日调度 | 已跑通 |
| `future_generic` / `linear_energy_hub` | 多能源载体、多设备类型，例如烟厂工业蒸汽和余热场景 | 将设备映射为通用组件，构建线性 Energy Hub 调度模型 | 烟厂 Level 3 已真实求解 |

建议理解方式：

- `current_cchp` 是“兼容旧实验代码”的后端；
- `future_generic` 是“面向导师项目和后续 15+ 场景扩展”的后端；
- 合作课题组后续容量优化器可以优先对接 `future_generic` 生成的标准系统对象、容量变量和调度接口。

## 4. 用户最小输入

用户最小需要提供以下信息：

| 输入类别 | 必填内容 | 推荐格式 | 说明 |
|---|---|---|---|
| 场景基本信息 | 场景 ID、名称、类型、地点、币种 | Excel 01 表或 `scenario.yaml` | 用于识别场景和报告输出 |
| 能源载体 | 用户需求、外部能源输入、自然/过程资源 | Excel 02 表或 `energy_carriers` | 例如电、冷、热、蒸汽、氢、天然气、太阳辐射、余热 |
| 负荷数据 | 至少一种可计算负荷曲线 | Excel 04 表或 CSV | 推荐 12 个月典型日，每月 24h |
| 资源/能源输入曲线 | 太阳辐射、风速、温度、余热、电价等 | Excel 05/07 表或 CSV | 缺失时部分场景可合成或使用默认值 |
| 候选设备 | 设备 ID、设备类型、是否启用、是否优化容量 | Excel 06 表或 `devices` | 技术经济参数可由默认设备库补齐 |
| 容量边界 | 设备容量上界、储能功率/能量容量上界 | Excel 06 表或设备字段 | 正式优化建议必须给；验收可使用默认上界 |
| 价格参数 | 电价、气价、容量电费等 | Excel 07 表或 `prices` | 支持 flat 和 24h 分时电价 |

## 5. 推荐数据粒度

当前支持以下输入粒度：

| 数据粒度 | 是否支持 | 用途 |
|---|---|---|
| 8760 全年逐时数据 | 支持 | 可用于聚类生成典型日，也可作为未来全年调度输入 |
| 12 个月典型日，每月 24h | 推荐 | 当前烟厂场景采用该方式，验收效率高 |
| 只提供部分月份典型日 | 可接入但会提示缺口 | 适合早期材料整理，不建议直接正式优化 |
| 月总量 | 可作为校核数据 | 可用于检查典型日曲线是否合理，后续可扩展为缩放依据 |
| 混合数据 | 需要数据质量报告 | 程序会尽量解析，但需要人工确认缺口 |

如果用户给 8760 数据，可使用典型日聚类入口生成代表日；如果用户只给月典型日，则按 12 个代表日构造典型日模拟。

## 6. 标准 `scenario.yaml` 结构

最小结构示意：

```yaml
schema_version: "1.0"
scenario:
  id: "example_scenario"
  name: "示例综合能源系统"
  scenario_type: "community_cchp"
  location: "example"
  currency: "CNY"

system:
  template: "cchp_ehc_base"

energy_carriers:
  demands: ["electricity", "heating", "cooling"]
  inputs: ["grid_electricity", "natural_gas"]
  resources: ["solar_resource", "temperature"]

data:
  load_file: "typical_profiles.csv"
  resource_file: "input_resource_profiles.csv"

simulation:
  mode: "typical_days"
  dispatch_horizon_hours: 24

prices:
  electricity:
    type: "tou_24h"
    unit: "CNY_per_kWh"
    values: [0.35, 0.35, 0.35]
  gas:
    type: "flat"
    unit: "CNY_per_kWh"
    value: 0.42

devices:
  pv:
    library_id: "pv_standard"
    enabled: true
    optimize_capacity: true
    capacity_ub_kw: 1000
```

## 7. 常用命令

### 7.1 校验场景

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\songshan_lake\scenario.yaml" --validate-only
```

看到以下信息表示可以走当前 CCHP 后端：

```text
Validation status: runnable
Backend: current_cchp
```

如果是未来通用后端场景，会看到：

```text
Validation status: future_supported
Backend: future_generic
```

这类场景需要显式使用 `--accept-future`，避免误把“未来支持”当作旧后端已可运行。

### 7.2 导出组件计划

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\tobacco_factory\scenario.yaml" --export-component-plan --accept-future --output "DesignResults\component_plan_tobacco"
```

输出：

- `generic_component_plan.json`
- `generic_component_plan.md`

用途：证明用户设备已经能映射为单元模块库中的抽象组件类型。

### 7.3 构建通用模型

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\tobacco_factory\scenario.yaml" --build-generic-model --accept-future --output "DesignResults\generic_model_tobacco"
```

输出：

- `generic_model_components.json`
- `generic_model_build_gaps.csv`
- `generic_model_build_report.md`

用途：检查组件、母线、容量变量和不可求解缺口。

### 7.4 跑松山湖容量配置

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\songshan_lake\scenario.yaml" --mode demo --output "DesignResults\three_scenario_acceptance\songshan_lake_demo"
```

### 7.5 跑德国容量配置

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\german\scenario.yaml" --mode demo --output "DesignResults\three_scenario_acceptance\german_demo"
```

### 7.6 跑烟厂 Level 3 通用后端真实求解

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\tobacco_factory\scenario.yaml" --run-generic-design --generic-search-levels 1.0 --solve-generic-dispatch --dispatch-month 1 --dispatch-periods 24 --accept-future --accept-default-bounds --output "DesignResults\three_scenario_acceptance\tobacco_factory_level3"
```

关键参数说明：

| 参数 | 作用 |
|---|---|
| `--run-generic-design` | 运行通用容量设计搜索 |
| `--generic-search-levels 1.0` | 使用容量上界作为验收候选方案 |
| `--solve-generic-dispatch` | 启用通用线性 Energy Hub 真实调度求解 |
| `--dispatch-month 1` | 求解 1 月典型日 |
| `--dispatch-periods 24` | 求解 24 小时 |
| `--accept-future` | 允许 future_generic 场景进入通用后端 |
| `--accept-default-bounds` | 对缺失容量上界使用验收默认值 |

### 7.7 跑烟厂 test 模式轻量双层优化

如果需要证明烟厂不只是“单点容量验收求解”，还可以运行轻量双层验证：外层用小规模差分进化生成容量候选，内层对每个候选执行 24h 通用调度求解。

```bash
rtk uv run python design.py --scenario "松山湖\单元模块库\ies_design\scenarios\tobacco_factory\scenario.yaml" --run-generic-design --generic-search-strategy de --generic-population 4 --generic-generations 1 --generic-random-seed 1 --solve-generic-dispatch --dispatch-month 1 --dispatch-periods 24 --accept-future --accept-default-bounds --output "DesignResults\tobacco_factory_bilevel_test"
```

当前 test 验证结果：

| 指标 | 结果 |
|---|---|
| 外层候选方案数 | `4` |
| 可行内层调度方案数 | `1` |
| 最优方案 ID | `0` |
| 最优方案调度状态 | `dispatch_solved=True` |
| 求解器终止状态 | `optimal` |
| 调度目标值 | `78835.84819047617` |

说明：轻量双层验证用于中期检查和接口闭环证明；正式容量优化仍建议由后续通用容量优化器或合作课题组优化器接入 `capacity_variables`、调度接口和目标函数后完成。

### 7.8 一键检查

```bash
rtk uv run python run_design_checks.py --include-tobacco-level3
```

看到 `ALL DESIGN CHECKS PASSED` 表示接口、默认库、场景校验、通用模型和烟厂 Level 3 求解均通过。

## 9. 如何新增一个场景

推荐流程：

1. 让用户或师弟填写 `课题组场景整理/课题组场景整理模板.xlsx`；
2. 用 Excel 解析器导出标准场景包；
3. 校验 `scenario.yaml`；
4. 导出通用组件计划；
5. 构建通用模型并查看缺口；
6. 补齐容量上界、价格、效率、COP、储能能量容量等关键参数；
7. 运行通用后端调度求解；
8. 导出容量配置结果和转换类型统计；
9. 再决定是否交给合作课题组容量优化器做正式双层优化。

对应命令骨架：

```bash
rtk uv run python design.py --excel "某场景.xlsx" --export-scenario --output "DesignResults\excel_export\某场景"
rtk uv run python design.py --scenario "DesignResults\excel_export\某场景\scenario.yaml" --validate-only --accept-future
rtk uv run python design.py --scenario "DesignResults\excel_export\某场景\scenario.yaml" --export-component-plan --accept-future --output "DesignResults\某场景_component_plan"
rtk uv run python design.py --scenario "DesignResults\excel_export\某场景\scenario.yaml" --build-generic-model --accept-future --output "DesignResults\某场景_generic_model"
rtk uv run python design.py --scenario "DesignResults\excel_export\某场景\scenario.yaml" --run-generic-design --solve-generic-dispatch --accept-future --accept-default-bounds --output "DesignResults\某场景_level3"
```

## 10. 设备如何抽象

模块库不按场景重复写设备，而是按输入输出和处理逻辑抽象为少数通用组件：

| 抽象组件 | 典型设备 | 建模逻辑 |
|---|---|---|
| `Source` | 电网、天然气源、太阳能、余热源 | 向某个能源母线供能，可带成本或固定曲线 |
| `Sink` | 电负荷、冷负荷、热负荷、蒸汽负荷 | 从能源母线取能，通常使用固定负荷曲线 |
| `Transformer` | CHP、锅炉、电制冷、热泵、吸收式制冷 | 输入一种或多种能源，按效率/COP输出目标能源 |
| `GenericStorage` | 电储能、冷储能、热储能、氢储能 | 带功率容量、能量容量、充放效率和 SOC 动态 |
| `Source_plus_Transformer` | 余热回收 | 先表示可回收资源，再转换为热或蒸汽 |

这种抽象的好处是：未来新增设备时，只要明确输入载体、输出载体、效率/转换系数、容量变量和成本参数，就能映射到通用组件，不需要为每个场景单独写一套模型。

## 11. 常见问题

### 11.1 为什么烟厂是 `future_supported` 但也能求解？

`future_supported` 表示它不能走旧版固定 CCHP 后端；但当前已经有 `future_generic / linear_energy_hub` 通用后端，所以需要显式加 `--accept-future --solve-generic-dispatch` 进入新后端求解。

### 11.2 `--accept-default-bounds` 能不能用于正式结果？

可以用于中期验收和流程打通，但正式工程结果建议补齐真实容量上界。报告中需要说明哪些容量来自用户输入，哪些来自默认库或验收默认值。

### 11.3 典型日和 8760 数据怎么选？

验收和快速接入推荐 12 个月典型日，每月 24h；如果已有 8760 数据，可以先聚类成典型日，再进入优化流程。

### 11.4 合作课题组应该对接什么？

建议对接 `future_generic` 生成的标准系统对象：

- 组件列表；
- 能源母线；
- 负荷和资源时序；
- `capacity_variables`；
- 给定容量后的调度求解接口；
- 输出的成本、能流、约束缺口和转换类型统计。
