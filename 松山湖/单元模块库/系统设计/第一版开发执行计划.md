# 场景化系统设计接口第一版开发执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: 使用 TDD 逐项实现；每个模块先补失败测试，再写最小实现，最后运行闭环验证。本文档按当前仓库状态编写，不要求自动提交 git commit。

**Goal:** 完成第一版场景化系统设计接口，使合作者可以通过 YAML 或 Excel 输入场景数据，调用现有 CCHP 优化后端完成系统设计，并得到可阅读的配置结果包和使用说明书。

**Architecture:** 第一版不重构 `operation.py` / `cchp_gaproblem.py`，采用接口适配层路线：`Excel/YAML -> resolved scenario -> current case_config -> run_comparative_study -> standard design package`。对氢、蒸汽等后续场景先在配置和校验层预留，不声明已经可真实优化。

**Tech Stack:** Python 标准库、`openpyxl`（通过 `uv run python` 环境）、现有 `geatpy/oemof/pyomo` 优化链路、CSV/JSON/Markdown 输出。

---

## 文件结构与职责

- `design.py`: 顶层 CLI，统一处理 `--scenario`、`--excel`、`--validate-only`、`--mode`、参数覆盖和结果导出。
- `松山湖/单元模块库/ies_design/excel_parser.py`: 读取 `课题组场景整理模板.xlsx`，转换为标准场景字典和中间 CSV 文件。
- `松山湖/单元模块库/ies_design/typical_day.py`: 读取已有典型日、从每月典型日生成当前后端兼容格式、从 8760 数据生成聚类典型日。
- `松山湖/单元模块库/ies_design/result_exporter.py`: 汇总 Pareto 结果，导出标准设计结果包和追溯文件。
- `松山湖/单元模块库/ies_design/scenarios/third_placeholder/scenario.yaml`: 第三场景占位，用于验证 15 场景扩展接口和 current_cchp 不支持设备的提示。
- `松山湖/单元模块库/场景化系统设计接口使用说明书.md`: 给合作者和导师看的使用说明书。
- `松山湖/单元模块库/ies_design/tests/`: 所有第一版模块测试。
