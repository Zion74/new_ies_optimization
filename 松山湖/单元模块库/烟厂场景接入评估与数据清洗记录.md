# 烟厂场景接入评估与数据清洗记录

## 1. 结论

烟厂场景可以作为第三个真实结构场景接入，而且比继续使用松山湖变体更适合证明单元模块库的通用性。

它不应走旧版 `current_cchp` 后端，而应走 `future_generic` / 通用模块后端。原因是旧版 CCHP 后端只支持固定冷热电结构，而烟厂场景涉及工业蒸汽、余热回收、热泵、储热水箱、太阳能资源和工业分时电价等内容。

当前适合的验收定位是：

1. 作为“第三个真实结构场景 / 单元模块库接口验收场景”：可以接入。
2. 作为“真实可计算容量优化场景”：还需要补齐通用后端设备映射、蒸汽/热水单位边界、数据文件导出和部分经济参数。

## 3. 场景特征

烟厂场景当前 Excel 中的主要内容如下：

| 类别 | 内容 |
|---|---|
| 场景编号 | `tobacco_factory_001` |
| 场景类型 | `tobacco_factory_multi_energy` |
| 用户需求 | 电负荷、冷负荷、蒸汽负荷 |
| 能源输入 | 电网购电、天然气 |
| 资源输入 | 太阳辐射、余热、环境温度 |
| 设备 | 光伏、燃气 CHP、电制冷、吸收式制冷、电储能、冷储能、蒸汽锅炉、余热回收 |
| 清洗后新增/启用建议 | 电热泵、热储能 |

这个结构与松山湖/德国的“冷热电 CCHP”不同，能够体现“工业电-冷-蒸汽/热水-余热-天然气”的多能转换场景。

## 4. 原始数据核查

`load_data.csv` 文件虽然扩展名是 `.csv`，但文件头是 `PK`，实际是 Excel 工作簿。它包含这些 sheet：

| sheet | 数据含义 | 时间范围/分辨率 |
|---|---|---|
| `production_data` | 生产计划 | 2025-01-01 至 2026-01-27，日尺度，部分缺日 |
| `weather_data` | 太阳辐射、室外温度、湿度 | 2025-01-01 至 2026-01-27，30 min |
| `ZS_JB_data` | 制丝/卷包供热相关负荷与水系统数据 | 2025-09-01 至 2026-01-27，30 min |
| `solar_data` | 太阳能系统温度和泵状态 | 2025-10-01 至 2025-12-24，30 min，部分时间缺失 |
| `cooling_load` | 制丝/卷包冷负荷及分项冷量 | 2025-01-01 至 2026-01-27，30 min |

因此，该场景数据不是纯手工模板，背后有真实运行/项目数据支撑。但 Excel 中的 12 个月典型日负荷仍带有整理和合成性质，不能直接等同于完整实测 8760 数据。

## 5. Excel 数据质量问题与处理

### 5.1 `04_用户负荷需求曲线`

原始问题：

| 问题 | 原始表现 | 处理 |
|---|---|---|
| 行数异常 | 应为 12 个月 x 24 小时 x 3 类负荷 = 864 行，原始为 894 行 | 删除重复组合 |
| 1 月前 10 小时重复 | 1 月 hour 1-10 的电/冷/蒸汽各重复一次，共 30 行重复 | 保留第一组，删除重复组 |
| 4 月蒸汽第 13 小时错位 | `M04/4/13/steam` 被写入 `profile_id`，导致字段错位 | 修正为 `M04, 4, 13, steam, 6.2, t/h` |
| 数值末尾逗号 | 个别单元格出现 `6.5,`、`1550,` 等手工格式 | 统一去掉逗号并转为数值 |

清洗后结果：

| 指标 | 结果 |
|---|---|
| 行数 | 864 |
| 重复组合 | 0 |
| 缺失组合 | 0 |
| 覆盖范围 | 12 个月 x 24 小时 x electricity/cooling/steam |

### 5.2 `05_能源输入与资源曲线`

原始问题：

| 问题 | 原始表现 |
|---|---|
| 月份不完整 | 只有 1、4、7、10 月 |
| 小时不完整 | 每月只有 1 点和 12 点 |
| 资源曲线不足 | 不足以直接支撑 12 个月典型日调度 |

处理方式：

1. 电网购电和天然气：扩展为 12 个月 x 24 小时，购能上限仍留空，表示不限。
2. 太阳辐射和环境温度：从原始 `weather_data` 中按 2025 年数据生成月-小时平均值。
3. 余热：由于完整余热资源曲线尚不明确，先基于原 Excel 的季节性锚点进行月度和小时插值/合成，并在备注中标记为 synthesized。

| input_id | 行数 |
|---|---:|
| `grid_electricity` | 288 |
| `natural_gas` | 288 |
| `solar_resource` | 288 |
| `waste_heat` | 288 |
| `temperature` | 288 |
| 合计 | 1440 |

## 6. 结题材料中找到的信息

### 6.1 设备容量上界

结题材料第 4 章建设内容中明确提到三类改造区域：

| 区域 | 设备 | 最大制热量 |
|---|---|---:|
| 动力中心地下管廊 | 2 台磁悬浮热泵机组 | 900.1 kW + 1314 kW |
| 联合工房制丝侧 | 1 台水源热泵、2 台四管制风冷热泵、1 台风冷热泵 | 1326.8 kW + 2 x 1513.5 kW + 1386 kW |
| 联合工房卷包侧 | 2 台水源热泵、2 台四管制风冷热泵、1 台风冷热泵 | 1326.8 kW + 243.7 kW + 2 x 1513.5 kW + 1386 kW |

合计最大制热量约为：

```text
900.1 + 1314 + 1326.8 + 2 * 1513.5 + 1386 + 1326.8 + 243.7 + 2 * 1513.5 + 1386
= 13937.4 kW
```

因此，清洗版 Excel 中将：

- `electric_heat_pump.capacity_ub = 13937.4 kW`
- `waste_heat_recovery.capacity_ub = 13937.4 kW`，作为接口验证阶段的保守约束，后续应替换为可回收余热实际上限。

### 6.2 储热水箱

结题材料给出：

- 制丝侧新增 `567 m3` 储热水箱；
- 卷包侧新增 `900 m3` 储热水箱；
- 合计 `1467 m3`。

清洗版 Excel 中临时将其折算为热储能能量容量：

```text
1467 m3 * 1000 kg/m3 * 4.186 kJ/(kg*K) * 15 K / 3600
= 25586.9 kWh
```

注意：这里假设有效温差为 15 K，仅用于接口验证。真实建模时需要导师或项目资料确认储热温区、可用温差、热损失和运行上下限。

### 6.3 蒸汽与热水边界

结题材料中明确提到空调系统适配性改造：将原蒸汽盘管替换为适配 45 摄氏度热水参数的热水盘管，用热水替代蒸汽后每年可减少蒸汽消耗 24000 吨。

这说明烟厂场景里“蒸汽需求”可能有两种表达方式：

1. 原系统口径：以 `steam` 表示原蒸汽消耗需求，单位为 `t/h` 或 `t`。
2. 改造后口径：以 `heat` 或 `hot_water` 表示 45 摄氏度以上热水供热需求，单位为 `kW/kWh`。

因此，后续接入模型时需要明确：优化器到底直接处理 `steam`，还是先把蒸汽替代量折算成热水热负荷。当前建议保留 `steam` 作为用户需求载体，同时在通用后端预留 `steam_to_heat` 或 `high_grade_heat_source` 转换。

### 6.4 投资成本

结题材料中找到项目批复总投资额控制 `4077 万元`，但没有找到单设备投资成本拆分。因此：

- 可以用于场景总投资背景说明；
- 不适合直接作为每类设备的投资成本；
- 真实优化前仍建议使用默认参数库补齐单设备投资成本，并在报告中标记来源。

## 8. 当前仍不能直接求解的原因

清洗版 Excel 已经适合作为第三真实结构场景输入，但还不能直接用旧求解后端跑容量优化，主要原因如下：

1. Excel 导入器仍默认写入 `system.template = cchp_ehc_base`，需要为 `tobacco_factory_multi_energy` 映射新的通用模板。
2. `current_cchp` 不支持 `steam_boiler`、`waste_heat_recovery`、`electric_heat_pump`、`heat_storage` 等烟厂设备。
3. Excel 导入器目前没有导出 `energy_capacity_ub`，导致热储能能量容量上界还不能进入 `scenario.yaml`。
4. 24 小时分时电价目前会被简化为 flat price，需要保留为 24h TOU 数组。
5. `load_file` 和 `typical_day_file` 仍未自动生成到场景配置中，需要把 04/05 表导出为通用后端可读的数据文件。
6. 蒸汽 `t/h` 与热功率 `kW` 的换算边界尚未定稿；如果直接以 `steam` 建模，需要单独的蒸汽载体和设备约束。

## 9. 建议接入路径

推荐路径：

```text
课题组场景整理模板_烟厂_清洗版.xlsx
  -> ExcelScenarioParser
  -> tobacco_factory_multi_energy scenario.yaml
  -> system.template = tobacco_factory_multi_energy 或 industrial_steam_cooling_base
  -> DefaultsResolver 补齐技术经济参数
  -> GenericBackendPlanner 生成组件计划
  -> GenericModelBuilder 生成通用系统模型
  -> evaluate_dispatch(capacities) / build_dispatch_model()
  -> demo 优化闭环验证
```

不推荐路径：

```text
烟厂 Excel -> cchp_ehc_base -> current_cchp
```

## 10. 后续开发任务建议

1. 新增 `tobacco_factory_multi_energy` 或 `industrial_steam_cooling_base` 系统模板。
2. 在 `scenario_catalog.yaml` 中注册 `tobacco_factory_multi_energy`。
3. 修改 Excel 解析器：
   - 按场景类型选择通用模板；
   - 导出 `energy_capacity_ub`；
   - 保留 24h 分时电价；
   - 导出标准负荷/资源 CSV；
   - 生成输入数据完整性报告。
4. 扩展通用后端：
   - 支持 `steam` 载体；
   - 支持 `fuel_to_steam`；
   - 支持 `waste_heat -> heat`；
   - 支持 `electricity + waste_heat -> heat` 热泵抽象；
   - 支持热储能功率容量和能量容量双变量。
5. 明确蒸汽换算口径：
   - 如果保留 `steam`：模型内以 `t/h` 建模；
   - 如果折算为热负荷：需要蒸汽压力、温度、焓值或统一折算系数。
6. 用清洗版 Excel 生成组件计划和通用系统模型，作为第三场景接入验收证据。

## 11. 需要继续确认的问题

1. 烟厂场景最终是按“原蒸汽系统需求”建模，还是按“改造后 45 摄氏度热水供热需求”建模？
2. 蒸汽 `t/h` 是否保留为独立能源载体，还是统一折算为 `kW` 热负荷？
3. 热储能的有效温差是否可以按 15 K，还是需要按设计供回水温度重新计算？
4. 光伏装机上限是否有屋顶面积或项目资料支撑？当前结题材料只提到少量光伏，没有找到屋顶面积。
5. CHP 是否确实属于该烟厂场景候选设备？结题材料主线更偏余热回收、热泵、太阳能光热和储热。
6. 蒸汽锅炉容量上界是否有原系统锅炉额定容量资料？
7. 单设备投资成本能否从工程清单获得？如果不能，是否同意先使用默认参数库。
